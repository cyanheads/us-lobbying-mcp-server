# us-lobbying-mcp-server — Design

## MCP surface

| Tool | Description | Main inputs |
|:--|:--|:--|
| `uslobbying_search_filings` | Search federal lobbying registrations and activity reports, preserving filing documents, amounts, issues, and disclosed participants. | Year, client/registrant, period, filing type, specific-issues text, issue code, continuation |
| `uslobbying_get_client_profile` | Resolve client records across retained firms, then assemble a selected client's lobbying history with separate income and expense ledgers. | `mode`, client name or selected client IDs, years, continuation |
| `uslobbying_get_issue_spending` | Aggregate the reported amounts on filings mentioning an issue, identifying overlapping issue coverage. | Issue code, years, optional client/registrant, continuation |
| `uslobbying_search_lobbyists` | Find lobbyists and retrieve filing evidence of their activities and disclosed covered government positions. | `mode`, name/registrant or lobbyist ID/year, continuation |
| `uslobbying_get_contributions` | Retrieve semiannual LD-203 reports and their complete contribution lists, PAC disclosures, and certifications. | Year, period, registrant/lobbyist, contribution filters, continuation |
| `uslobbying_search_foreign_agents` | Search FARA registrants and foreign principals, or retrieve a registration's principal, short-form, or document records. | `mode`, entity, name/country/status or registration number/detail, continuation |
| `uslobbying_list_reference` | Decode issue codes, filing types, government entities, contribution types, identifiers, and source limitations. | `topic`, optional `filter` |
| `uslobbying_dataframe_query` | Materialize read-only SQL results and retrieve complete rows in bounded windows. | `canvas_id`, `sql` or `result_table`/`offset`, `row_limit`, optional `register_as` |
| `uslobbying_dataframe_describe` | Inspect staged tables, columns, acquisition coverage, and provenance before querying. | `canvas_id`, optional `table_name` |
| `uslobbying_dataframe_drop` | Remove a staged table before expiry when deletion is enabled. | `canvas_id`, `table_name` |

No resources, prompts, or app tools. Tool-only clients can complete every workflow. Upstream tools use `readOnlyHint: true`, `idempotentHint: true`, `openWorldHint: true`; reference and dataframe describe use `openWorldHint: false`. Dataframe query creates derived local state: use `readOnlyHint:false`, `destructiveHint:false`, `idempotentHint:false`, `openWorldHint:false`; repeated new SQL calls can create separate tables. Drop uses `readOnlyHint: false`, `destructiveHint: true`, `idempotentHint: true`, `openWorldHint: false` because it removes an existing table. Register drop through `disabledTool()` while `USLOBBYING_DATAFRAME_DROP_ENABLED` is false, retaining the manifest enable hint.

## Overview and requirements

Official US federal influence disclosures for journalists, ethics researchers, governance analysts, policy advocates, and compliance researchers. LDA covers registrations, quarterly activity, covered-position disclosures, and semiannual contribution reports. FARA covers foreign-principal representation, individual short forms, and filing-document links. Neither source establishes wrongdoing, current employment, policy outcomes, or influence scores.

1. Find activity or registration filings and follow their official documents.
2. Resolve a client across retained firms without conflating similarly named entities.
3. Compare reported amounts by year and issue without counting amendments or income/expense overlap twice.
4. Trace a lobbyist's disclosed positions to the filing that actually contains them.
5. Inspect LD-203 contribution lists without confusing reports with individual donations.
6. Find FARA registrants by name or represented country, then inspect registration details.
7. Stage acquired analytical records and join/group them with SQL.

Support Bun and Node, STDIO and Streamable HTTP; `sessionMode: 'stateless'` is sufficient because continuations and canvases are server-side tokens rather than MCP session state. No deployment or public endpoint is specified. Workers are outside this build: native DuckDB is unavailable there. Anonymous upstream access is the baseline; no key is needed. Keep current project version metadata unchanged during implementation.

LDA responses include access timestamps and the attribution: “Senate Office of Public Records cannot vouch for the data or analyses derived from these data after the data have been retrieved from LDA.gov.” Preserve source text and identify computed fields as derived; never use the Senate Seal. The [LDA API terms](https://lda.gov/api/tos/) permit end use but prohibit misrepresentation and throttle circumvention. FARA's [API](https://efile.fara.gov/ords/fara/f?p=API:ENDPOINTS) and [bulk repository](https://efile.fara.gov/ords/fara/f?p=107:21) explicitly support machine access and bulk download; no additional license or AI-specific permission was found there. This does not assert unrestricted rights in every attached PDF.

Runtime search uses the official daily XML ZIP alternatives because the CSV snapshots contain unescaped interior quotes and cannot be parsed completely without guessing field boundaries. `FARA_All_Registrants.xml.zip` is 313922 bytes, inflates to 2483177 bytes, and contains 7097 `REGISTRANTS/ROW` records. `FARA_All_ForeignPrincipals.xml.zip` is 971725 bytes, inflates to 9058184 bytes, and contains 17776 `FOREIGNPRINCIPALS/ROW` records. Both parse as well-formed XML after lossless Latin-1 decoding. Registrant XML fields include `Registration_Number`, `Registration_Date`, optional `Termination_Date`, `Name`, and sparse address/business fields. Principal XML uses `Foreign_principal`, `FP_registration_date`, optional `FP_termination_date`, `Country_location_represented`, `Registration_number`, `Registration_date`, and `Registrant_name`. Preserve missing elements, strings, whitespace, XML-decoded entities, and unknown fields; omitted termination elements identify active records in these snapshots. Of 17776 principal records, 16629 lacked ZIP and 15165 lacked city. Registrant and principal snapshots suffice for search; do not download the document or short-form corpus to answer a registrant search.

FARA JSON field adapters are endpoint-specific, not a recursive case converter. Registrant list keys include `Registration_Number`, `Registration_Date`, `Name`, optional `Business_Name`, `Address_1`, `Address_2`, `City`, `State`, `Zip`. Principal detail uses `REG_NUMBER`, `REG_DATE`, `REGISTRANT_NAME`, `FP_NAME`, `FP_REG_DATE`, `COUNTRY_NAME`, `ADDRESS_1`, `ADDRESS_2`, `CITY`, `STATE`, `ZIP`. Short forms use `REG_NUMBER`, `REG_DATE`, `REGISTRANT_NAME`, `SF_FIRST_NAME`, `SF_LAST_NAME`, `SHORTFORM_DATE`, and uppercase address fields. RegDocs uses `REGISTRATION_NUMBER`, `DATE_STAMPED`, `REGISTRANT_NAME`, `DOCUMENT_TYPE`, `URL`, `SHORT_FORM_NAME`, `FOREIGN_PRINCIPAL_NAME`, `FOREIGN_PRINCIPAL_COUNTRY`. Require identifying fields, allow absent/null optional fields, preserve additional source keys. Validate complete raw JSON/XML trees with `JsonValueSchema` before endpoint schemas; unsupported own `__proto__` keys fail `source_schema_changed` rather than disappearing during object parsing. Reject an XML `__proto__` element before XML parsing for the same reason. Normalize only the verified envelope alternatives (row array, singleton object, empty rowset string); other shapes are schema failures.

## Shared input, output, and acquisition rules

All schemas use serializable Zod types and descriptions on every field; input roots and nested filter objects are strict. No arbitrary upstream parameter bag. Normalize blank optional strings to omitted, trim identifier whitespace, uppercase issue/filing codes, lowercase enumerated modes, and normalize canonical UUID casing. Numeric IDs are digit strings; accept losslessly validated safe upstream integers at the source edge and serialize as strings. Never round an unsafe upstream number. Names remain literal text; no fuzzy merging. Unknown issue/country/type values fail with a named reference-tool recovery.

Each data response includes `source` (`lda` or `fara`), `retrieved_at` ISO timestamp, `effective_filters`, `notices:string[]`, and `coverage`. LDA includes `attribution` verbatim above. Coverage is `{complete:boolean, pages_fetched:number, records_fetched:number, unique_records:number, upstream_count?:number, started_at:string, finished_at?:string, next_cursor?:string}`. Counts are explicit about upstream rows versus deduplicated records; a completed sequence means links exhausted, not a transactionally frozen upstream snapshot. FARA adds `snapshot_retrieved_at`, `snapshot_source_urls`, and `snapshot_last_modified?` when the server actually supplied that header.

LDA list tools accept `page_size` integer 1–25 (default 25), `max_pages` integer 1–5 (default 1), and optional opaque `cursor`; FARA returns one locally paged result window per call and has no `max_pages` input. The page bound is a per-call workload limit with a continuation, never a corpus cap. Start analytical scans with default `max_pages:5`. Tool-call deadline is 45 seconds; individual network exchanges at most 20 seconds, retries included inside the remaining call deadline. If there is not enough time to start another page, return committed progress and a cursor; do not launch work after returning. A network failure fails the call, retaining the prior committed continuation so it can be retried.

Continuations live in tenant-scoped `ctx.state`, expire at a common absolute deadline 24 hours after acquisition starts, and bind the originating tool, normalized filters, scan kind, page/partition position, result chunk references, and acquisition start time. Echo `cursor_expires_at`; child chunks must not expire before their scan. Returned cursor tokens are random IDs, never arbitrary URLs. On continuation, unchanged filters may be omitted or repeated; changed filters reject. Query/mode fields on cursor-capable tools are optional in the advertised schema: requirements in the tool tables apply to the first call and are checked in the handler after cursor resolution. Resolve source `next` links only after verifying HTTPS, fixed host/path, allowed query keys, and page progression; rebuild the request from stored filters. Detect repeated pages/links and fail `pagination_invalid`, never mark complete. No endpoint URLs or credentials are caller supplied.

Use one mutable scan manifest with a monotonically increasing revision, a current random cursor, and the immediately preceding cursor's cached response and successor. Retrying the preceding cursor replays that response; advancing its successor replaces the replay slot. Older cursors fail `cursor_invalid` rather than restarting or advancing silently. Serialize operations for the same scan in a bounded process-local registry and release the lock on settle. Write new chunks before publishing the manifest through one `ctx.state.set`; deterministic chunk keys make retry after an interrupted chunk write safe. Acquisition failures must not publish a new revision. The framework does not promise a multi-key transaction or crash-atomic filesystem writes: an unreadable manifest/chunk invalidates the cursor with explicit restart recovery, never a partial success. A response lost after successful publication is recovered by the replay slot. This is a single-process service: shared storage does not make process-local locks or upstream budgets replica-safe. No per-revision checkpoint chain, per-row KV entries, or background continuation worker.

Keep acquired data in immutable independently stored chunks containing at most the current call's five source pages (125 rows at page size 25). Never rewrite a committed chunk while preparing another revision. Dedup-index shards use copy-on-write only for affected shards; the manifest selects the committed shard revision. Unpublished chunks/index revisions are ignored and may be safely overwritten on retry; reclaim replaced index shards after manifest publication. Do not use one key per UUID or a repeatedly rewritten full source array. Raw search cursors retain only undelivered rows, dedup state, and replay state; analytical scans retain all acquired rows until completion/expiry. Stream chunks for finalization instead of loading the full corpus and all three canvas tables into JS simultaneously. Source UUID deduplication is mandatory across pages and overlapping partitions. Upstream updates can still shift pages; disclose this live-API limitation rather than promising a historical snapshot.

The framework's default in-memory provider has a **10000-entry global ceiling**, not a configurable per-tenant unlimited store. One 96955-row year needs approximately 776 source chunks when every call commits five full pages (up to 3879 if calls commit only one), plus manifests/index shards; storing each response and historical checkpoint indefinitely would consume that budget unnecessarily. Bound retained in-memory acquisition data to 128 MiB process-wide, measured by serialized UTF-8 bytes including indexes/replay state, and refuse before advancing a checkpoint when capacity is unavailable. This is a resource refusal, never a successful truncated acquisition. Retain the in-memory default and warn that broad scans can exhaust it. An operator may explicitly select framework `STORAGE_PROVIDER_TYPE=filesystem` and a writable `STORAGE_FILESYSTEM_PATH` for larger durable scans; document the retained public records and expiry behavior rather than silently writing persistent copies. Filesystem storage removes the in-memory ceiling but still can fail on disk capacity. In either provider a missing chunk invalidates the cursor; never skip it or publish totals. Expiry or an in-memory restart requires a fresh scan; filesystem checkpoints survive restart until their absolute expiry. Capacity/disk failure preserves the last committed checkpoint where possible and returns `acquisition_storage_unavailable` with narrowed-scope/configuration recovery. A scan whose paced duration exceeds 24 hours requires separately requested year/client/registrant scopes; no claim of unlimited completion or automatic merging across independent scopes.

Source-result windows use a **24000 UTF-8 byte full-result target**, including structuredContent, its formatted twin, links, metadata, and envelope allowance. Stop between complete parent records and retain the undelivered tail before fetching another page; `max_pages` counts fetched pages, not response windows. If a parent cannot fit, return a small `record_handles` entry `{record_handle, source_id, record_bytes, expires_at, retrieval_tool}` instead of the oversized value; mark `records_deferred` explicitly, never count a handle as a delivered full record. The same source tool exposes the shared record-window inputs below. Keep the exact stored parent reachable until its advertised expiry, including after the ordinary search cursor advances; retained handle data counts against the existing storage budget. Analytical finalized lists/rows use the same windowing and record handles, with exact total/shown/deferred counts and a cursor even when acquisition is complete. Parent identity and nested list membership remain intact across windows; never pretend a child page is a complete LD-203 parent.

### Shared stored-record retrieval

`record_limit` bounds only object entries and array items. Text windows return the largest Unicode-code-point fragment allowed by the response byte budget, independently of `record_limit`.

Every data-producing source tool accepts optional `record_handle`, `record_path` (JSON Pointer, default empty root), `record_offset` (nonnegative integer, default 0), and `record_limit` (integer 1–25, default 25). A handle request is exclusive with source filters, modes, acquisition cursor, and canvas inputs; it reads only that tool's tenant-bound stored record without another upstream request. Validate pointer traversal with own-property checks; reject invalid paths/offsets as `invalid_filter`, and unknown/expired/other-tool handles as `cursor_invalid`. Handles are random tokens, not filesystem paths or caller-supplied source IDs.

Return common provenance plus `record_window:{record_handle,path,kind,total,offset,returned,next_offset?,complete,entries?,items?,text?,value?}` and `retrieval_tool`. Objects expose key-ordered `entries:[{key,path,value?}]`; arrays expose indexed `items:[{index,path,value?}]`. Include each child value only if it fits whole; otherwise omit `value` and return its exact child path so the caller can descend with the same handle. Page the complete key/element sequence, reducing the number returned until the full result fits 24000 bytes. Oversized strings use `kind:"string"`, `text`, and offsets/counts in Unicode code points; choose the largest complete-code-point fragment fitting the full-result target and expose `next_offset` until the entire original string is recoverable by concatenation. Scalar null/boolean/number values use `kind:"scalar"` and `value`. Empty objects/arrays/strings preserve their kind and total zero. `complete` describes the selected path's current delivery, never claims that omitted child values were returned. Both response surfaces carry identical windows and paths; no source text, unknown field, or child disappears. This one shared selector handles top-level sections, nested contribution/activity lists, and unusually long leaf text without a new tool or duplicate record copy.

`format()` carries every output value, null, nested field, notice, cursor, provenance field, and dataset pointer. Use a complete pretty-printed JSON text block for lossless structured data, choosing a fence longer than any run in source text; append official document URLs as Markdown links. This preserves CR/LF through JSON escapes and avoids lossy Markdown tables. Do not truncate specific-issues text, contribution lists, or FARA names. All upstream names, descriptions, covered positions, comments, and document titles are quoted record data, never instructions.

## Domain accounting

**Quarterly selection.** For analytic ledgers, acquire all filing types for the selected year/client/registrant scope, not merely `Q1`–`Q4`. Exclude `RR`/`RA` from spending. Group quarterly report/termination/amendment/no-activity variants by `(registrant.id, client.id, filing_year, filing_period)`, deduplicate UUID, then choose greatest `dt_posted`. Preserve `selected_filing_uuid`, all `superseded_filing_uuids`, and `selection_method:"latest_posted_within_relationship_period"`. This is a documented analytical rule, not an upstream-confirmed legal amendment chain. Equal latest timestamps with distinct UUIDs are `ambiguous` groups: retain candidates, exclude their amounts from sums, count and disclose them. Never use UUID lexical ordering to manufacture certainty. Unknown filing variants remain visible but excluded from aggregates pending explicit classification.

Apply issue/amount/text predicates **after** quarterly selection for analytics: otherwise an amendment removing an issue can leave its superseded original counted. Search remains raw filing discovery and returns all matched versions, explicitly `amendment_policy:"all_versions"`. Early years may use semiannual activity periods; retain them in search but do not force them into quarterly spending totals.

**Money.** Income and expenses are separate nullable decimal strings in USD. Parse decimal cents to `bigint` for exact addition, return decimal strings, and keep missing values missing. `0.00` is an explicit zero; null is unknown, not zero or a reportable threshold. Return known-value sums together with known/missing/ambiguous filing counts. Never derive a grand total by adding firm income to organization expenses: organization expenses can already include retained-firm payments ([official guidance, expense reporting](https://lobbyingdisclosure.house.gov/ldaguidance.pdf)). Do not infer a clean “in-house cost” by subtracting reported firm income. Expense-method codes A/B/C remain separate dimensions.

**Client identity.** LDA client records belong to registrant relationships; a client ID does not assert the complete corporate identity across retained firms. Name resolution returns all candidates with registrant, jurisdiction, effective date, and descriptions. A profile aggregates only caller-selected IDs and echoes them. Do not merge parent/subsidiary, punctuation variants, or aliases automatically. The profile describes the selected records, never an unqualified “complete corporate footprint.”

**Issue amounts.** A filing has one income/expense amount and several activities. Count a filing once per requested issue, even if that issue appears in multiple activity rows. Preserve `issue_count` and `multi_issue_filing_count`; sums mean “reported amounts on filings mentioning this issue,” not issue-specific spending. Issue buckets overlap and cannot be summed into a national total. Activity child tables contain **no monetary amount**, preventing accidental multiplication when joined.

**LD-203.** `contribution_items` are report children, not the parent envelope's rows. Return full parent lists even if a contribution predicate selected the report, plus explicit `matched_item_indexes` computed locally using all item predicates on the same child. Local text predicates use case-insensitive literal substring matching; dates and type use exact normalized values. When child filters are present, omit candidate reports with no same-child match; with no child filters, every item index matches and no-contribution reports remain eligible. Deduplicate reports by UUID; preserve repeated identical child rows with `item_index` because the source provides no item ID. Retain amendments and their types in report search; do not offer cross-report donation totals that count original and amended lists together. PAC names identify disclosed PAC relationships, not proof that every item was paid by that PAC. Honorary/meeting/library/inaugural payments are distinct from FECA donations.

## Tools — detail

The common fields, coverage contract, and source models above apply to every subsection. Flat object inputs preserve fields in clients that flatten root unions. Mode-specific invalid combinations fail before any upstream request. Search no-hit notice is emitted only when the complete selected scope is exhausted; an empty intermediate page with `next_cursor` says the scan is incomplete.

## DataCanvas contract

Completed analytical output uses flat typed fields: `annual_ledgers`, `selections`, `firms`, `issue_codes`, `targeted_entities`, `selected_filings`, `activities`, and `raw_filings`. A shared cursor pages these sets in that order; `row_set_totals` and `row_set_offsets` identify each set's exact size and delivered/deferred position. A missing list in one window means no rows of that kind were delivered in that window, not an empty complete set. Every raw and selected source filing remains available inline or through a deferred record handle, including when SQL is enabled.

Canvas is opt-in through framework `CANVAS_PROVIDER_TYPE=duckdb`; keep the default `none`. Install `@duckdb/node-api` as a production dependency for npm/Docker analytical capability. Wire the accessor in `setup(core)`. When canvas is enabled, a completed profile/issue scan stages all acquired and selected filings and selected activities; complete inline delivery remains available too. Use the shared 24000-byte UTF-8 full-result target and explicit schema, with no acquisition row cap. A supplied `canvas_id` means reuse that existing canvas, never silently mint a substitute if it expired. Final analytical responses include typed lists, `canvas_available`, and optional `dataset`; when canvas is disabled, return every final row through locally paged continuations and `canvas_available:false`, with no canvas token or claim that omitted rows are staged. These final-result cursors retain `status:complete` and complete acquisition coverage while advancing only the final row window; `coverage.next_cursor` still indicates remaining output. Explicit configuration errors and staging failures surface; never catch-log-return a successful incomplete table.

Dataset payload is `{canvas_id, tables:[{table_name,row_count,columns,grain,complete,created_at,expires_at}], describe_tool:"uslobbying_dataframe_describe", query_tool:"uslobbying_dataframe_query", guidance}`. Guidance names actual table names and both tools. **Every response containing `canvas_id`, including dataframe tools and derived-table results, contains these pointers.** Register fresh names rather than replacing prior datasets. Provenance in tenant `ctx.state` is keyed by canvas and table; framework table metadata is authoritative for lifecycle/schema. No global shared tenant canvas hidden from the caller. A new caller without a token cannot enumerate existing canvases; possession of a token permits access to every table in that canvas. Under unauthenticated HTTP every caller shares tenant `default`, so tokens and query/filter history must not appear in logs or another caller's response. Canvas contains only the acquired public disclosures and their derived data, including source-published personal details; no credentials, private caller documents, or inferred private identities. Scope authenticated canvases through the framework tenant boundary.

Finalized analytical delivery traverses `annual_ledgers`, `selections`, `firms`, `issue_codes`, `targeted_entities`, `selected_filings`, `activities`, then `raw_filings` through the same source tool's cursor. Each response contains only the typed lists delivered in that window, exact `row_set_totals`, and `row_set_offsets` counting records already delivered or deferred; traverse every set before clearing the final cursor. Top-level lists avoid redundant tagged wrappers and keep known schema paths within the formatter linter's depth. The complete acquired versions remain available rather than requiring a fresh search against changed upstream data. Every summary is windowed under the same response budget. With canvas, register every raw/selected/activity row before advertising the dataset. Partial tables never appear as complete; a staging timeout/failure retains acquisition state for retry and directs persistent failure to a narrower source scope. Selection consumes replayable chunks incrementally, retaining latest candidates and UUID decisions; raw table staging and final-record materialization replay those chunks without buffering another corpus. Canvas registration is one awaited operation per table; no detached ingestion or partial table append protocol.

| Table grain | Required columns and rules |
|:--|:--|
| One raw filing | UUID, registrant/client IDs, type/year/period/posting time, `income_usd VARCHAR`, `expenses_usd VARCHAR`, method, JSON disclosure fields, `selection_status`, and `selected_filing_uuid` linking superseded versions to the winner when unambiguous. Unknown fields remain in `source_fields`; complete original records also remain available inline. Null stays null. |
| One selected relationship-period filing | Same money columns, selected UUID, `issue_count`, `ambiguous` flag; only unambiguous selected filings enter sums. |
| One filing/activity | UUID, zero-based activity index, issue code, description, JSON lobbyists/government entities. **No money column.** |

Related tables share the filing UUID. Source record and child JSON preserve nested/sparse fields. Explicit `ColumnSchema` types are supplied even when leading values are null or zero. The framework's column type union has no DECIMAL: keep monetary columns `VARCHAR`, and use `CAST(income_usd AS DECIMAL(38,2))` in SQL for exact sums. Never infer `BIGINT`/`DOUBLE` money columns from a preview. Synthetic example: `SELECT filing_year, SUM(CAST(income_usd AS DECIMAL(38,2))) FROM df_SYNTHETIC_SELECTED WHERE selection_status = 'selected' GROUP BY filing_year`; actual table names come from the dataset payload.

### Dataframe tools

| Tool | Inputs | Output |
|:--|:--|:--|
| `uslobbying_dataframe_describe` | Required `CanvasIdSchema`; optional existing `table_name` | Canvas pointers, `tables` containing exact row count, column name/type/nullability, grain, source tool, effective filters, acquisition coverage/timestamps, lifecycle timestamps. Empty canvas returns empty array; unknown named table throws `missing_table`. |
| `uslobbying_dataframe_query` | Required canvas ID; either nonblank `sql` plus optional fresh `register_as`, or `result_table` plus `offset` (nonnegative integer, default 0); `row_limit` integer 1–100 default 25 | Canvas pointers and dataset, `result_table`, `columns`, JSON-safe `rows`, exact `row_count`, `rows_returned`, `offset`, optional `next_offset`, `output_complete`, and `row_order:"canonical_values"`. |
| `uslobbying_dataframe_drop` | Required canvas ID and table name | Canvas pointers, requested table name, `dropped:boolean`; absent table is false. Unknown canvas uses the drop-specific recovery below. |

Query delegates the single-statement SELECT/CTE gate and file/network/extension denial to DataCanvas. Preserve its `invalid_sql`, `missing_table`, `sql_execution_error`, `non_select_statement`, `multi_statement`, `denied_function`, `sql_read_only`, `plan_operator_not_allowed`, `sql_parse_error`, and `register_as_clash` distinctions; do not rebuild SQL parsing with regexes. Materialize each new SQL result through `query({registerAs, preview:0})`, using the caller's fresh name or a generated fresh name, so even the first response has an exact count and a stable remaining-data handle. SQL `ORDER BY` still determines a caller's SQL `LIMIT` selection, but delivery windows deliberately use canonical value ordering: `SELECT * FROM <quoted-result-table> ORDER BY ALL LIMIT <validated-window> OFFSET <validated-offset>`. State this ordering in the tool description; do not imply preservation of the original presentation order. Equal rows are interchangeable, so advancing by delivered rows preserves duplicate multiplicity. Retrieval accepts only a known materialized result table belonging to this canvas; changing SQL requires a fresh materialization. No OFFSET continuation over a re-executed, unordered original query, and no separate query-cursor store.

Return only whole rows fitting a **24000-byte UTF-8 full-result budget**, counting structuredContent, pretty JSON text, Markdown links, metadata, and envelope allowance together. Read at most `min(row_limit, framework canvas row limit)` candidates per window, then advance `next_offset` by the number actually delivered, not the candidate count. Echo the effective row limit if clamped by framework configuration. The full materialization remains reachable via the returned `result_table`/`next_offset` in this same tool; `output_complete` concerns delivery, not table completeness. If one complete row cannot fit, throw `query_row_too_large` without advancing; include the canvas/result-table handle and describe/query pointers in its error data, and direct the caller to SELECT fewer columns or explicit SUBSTR windows of the oversized value. Do not silently trim strings, drop columns, or return an empty page that cannot progress. Table metadata and query text can also exceed the envelope budget; reject with the same actionable projection recovery rather than promising a universal maximum for arbitrary SQL output. BIGINT/DECIMAL values follow the provider's lossless JSON serialization. Expired/dropped materializations fail `missing_table`; restart the original SQL only by an explicit new call.

MCPB cleaning deliberately strips platform DuckDB natives. `manifest.json` therefore fixes `CANVAS_PROVIDER_TYPE=none`; bundle installs expose inline data and actionable `canvas_unavailable` from dataframe tools. Do not offer a bundle setting that promises working DuckDB. npm/Docker users can enable canvas; an explicitly enabled but missing/broken native fails honestly. No runtime native download or automatic filesystem installation.

Drop catches `canvas_not_found` and re-raises through its own `ctx.fail` so it does not inherit a misleading re-stage-to-delete hint. No recovery or suggestion routes to disabled drop. Notices include effective local issue filtering, acquisition incomplete/next cursor, absent monetary values, ambiguous selection, overlapping issues, raw amended LD-203 lists, snapshot age, and canvas unavailability; declare optional notice/echo enrichment and render every field on both consumption paths.

Cross-tool calls and retries share their source pacer; tenants do not get independent upstream budgets. Separate processes sharing an originating IP remain a deployment constraint. No per-session pacer, detached refresh timer, or request-start race.

Use framework `createPacer` inside `withRetry`, wrapping fetch **and body read**; at most one retry per page within the tool's 45-second deadline. Cancellation reaches queue, exchange, parser iteration, and canvas registration; do not swallow caller abort. HTML received for a successful JSON request is an upstream availability failure; valid but incompatible JSON is schema change. FARA non-JSON 429 is classified by status before parsing. No speculative retry of arbitrary thrown errors.

FARA snapshot cache is process-wide, shared public data, single-flight per dataset, TTL 24 hours, at most the two required search datasets; no unbounded query-key cache. First request downloads only required snapshots; a principal search joins registrant snapshot only when registrant fields are requested by the fixed output. Pin each search's matched rows and snapshot provenance into its continuation chunks, so cache refresh between calls cannot skip, duplicate, or change that search's results. Refresh is awaited in-request, never detached. Extract ZIP members in memory without writing member paths to disk. Decode declared ISO-8859-1 bytes losslessly before parsing using Node `Buffer.toString('latin1')` (also supported by Bun); Web `TextDecoder('iso-8859-1')` aliases Windows-1252 and does not preserve the ISO C1 byte range. The framework XML convenience wrapper does not expose the required lossless options, so use its vetted `fast-xml-parser` peer directly. Validate root/row shapes and records; do not accept an HTML error ZIP or infer zero rows from parsing failure. Keep source spellings and raw dates alongside normalized calendar dates. Use native Web/Node APIs plus vetted ZIP/XML packages; no unofficial LDA/FARA SDK.

## Verification strategy

Inject the network boundary (`fetch`-compatible transport) into source services and keep source parsers and accounting pure. Use synthetic fixtures with real field names, never copied personal records. Fake timers drive process-wide pacing, retries, deadlines, cache TTL, and continuation expiration; no sleeps or wall-clock assertions. Use `createMockContext()` for definitions and exercise the framework invocation boundary for argument and output parsing.

Required cases: LDA 25-row pages and different next pages; ignored upstream parameter prevented by allowlist; zero/malformed/404; duplicate UUIDs across pages; item-filter duplicate parent reports; unknown/sparse nested fields; null versus zero amounts; original/amended/no-activity/termination selection; issue removed by later amendment; duplicate same-issue activities; equal-time ambiguity; cross-firm client IDs never auto-merged; expense/income never added; exact large/fractional decimal arithmetic; contribution no-items/PAC/null and mixed matching/nonmatching children; FARA missing address fields and numeric/string IDs/ZIP; singleton/array/ROWSET-empty; ISO-8859-1 accents/C1 bytes, XML entities, literal quotes, multiline XML values and postal leading zeroes; DTD rejection and malformed XML never partial success; separate principal/registrant status; live plain-text 429 and HTML errors; snapshot failure never empty success.

Continuation tests prove every synthetic source row is eventually reachable, no page or oversized response tail is skipped on a deadline, immediate replay does not duplicate progress, older cursors reject, interrupted writes preserve the prior manifest, malformed/off-origin next links fail, changed filters fail, and incomplete scans never expose final totals. Include default-provider entry/byte exhaustion, lost chunks, absolute expiry during a long scan, filesystem restart recovery, and FARA cache refresh during pagination. Concurrency tests call different tools simultaneously and prove a single source budget, including retries. Cancellation leaves no detached work or partial advertised table. Canvas tests inspect explicit schema with null-leading money, complete staged rows versus preview, pointers on **every** canvas-token branch, exact materialized count, byte-window progress by delivered rows, duplicate-row multiplicity under canonical ordering, query rows larger than the full wire budget, narrow projection/SUBSTR recovery, expired token/table recovery, DROP/ATTACH/COPY/external read denial, drop enabled/disabled registration, and MCPB no-native delivery of every acquired raw/selected/activity row. Measure full serialized result bytes with both response surfaces; a row-count-only assertion cannot verify the wire budget.

For every tool, inspect both structuredContent-only and content[]-only results, including errors, empty rows, long multiline descriptions, source links, nested lists, cursors, notices, and dataset metadata. Round-trip the JSON text block and compare every field to structured output; separately verify document links. For oversized source parents, reconstruct the complete original record through handle/path windows, including unknown keys, large child arrays, and multibyte strings, and assert exact equality without a duplicated source_record copy. Verify full-result windows remain within 24000 UTF-8 bytes and deferred handles remain readable after the acquisition cursor advances.

Run `bun run devcheck` raw, `bun run test`, and `bun run rebuild`; independent verification owns authored tests. A later paced live field pass covers each registered tool, continuation completion on a narrow scope, sparse/empty cases, one exact accounting example, enabled canvas SQL and disabled drop, and both response surfaces. No deliberate quota exhaustion and no production listener or deployment is needed for this design.

## Known limits and decisions

The broad issue workflow is intentionally expensive because the official LDA API has no verified issue-code filter and limits pages to 25. Resumable acquisition makes this honest; partial sums would make it misleading. Large live scans are not immutable snapshots and may expire before completion. Explicit selected client IDs preserve the footprint workflow without pretending the source offers a corporate identity graph. Latest-posted selection is reproducible but not proof of a legal amendment lineage. Reported amounts are rounded estimates with gaps; issue associations and contribution categories do not establish policy influence. FARA bulk search is daily rather than live, and no registration number is a general cross-source identity. These limitations are returned with results, not hidden in README prose alone.
