# us-lobbying-mcp-server — Design

## MCP surface

| Tool | Description | Main inputs |
|:--|:--|:--|
| `uslobbying_search_filings` | Search federal lobbying registrations and activity reports, preserving filing documents, amounts, issues, and disclosed participants. | Year, client/registrant, period, filing type, specific-issues text, issue code, location filters, `include`, `page_size`, continuation |
| `uslobbying_get_client_profile` | Resolve client records across retained firms, then assemble a selected client's lobbying history with separate income and expense ledgers. | `mode`, client name or selected client IDs, years, `row_sets`, `include`, continuation |
| `uslobbying_get_issue_spending` | Aggregate the reported amounts on filings mentioning an issue, or on a registrant's filings across every issue, identifying overlapping issue coverage. | Issue code or registrant, years, optional client, `include`, `row_sets`, continuation |
| `uslobbying_search_lobbyists` | Find lobbyists and retrieve filing evidence of their activities and disclosed covered government positions. | `mode`, name/registrant or lobbyist ID/year, `include`, continuation |
| `uslobbying_get_contributions` | Retrieve semiannual LD-203 reports and their complete contribution lists, PAC disclosures, and certifications. | Year, period, registrant/lobbyist, contribution filters, continuation |
| `uslobbying_search_foreign_agents` | Search FARA registrants, foreign principals, or short-form registrants, or retrieve a registration's principal, short-form, or document records. | `mode`, entity, name/country/status or registration number/detail, continuation |
| `uslobbying_list_reference` | Decode issue codes, filing types, government entities, contribution types, countries, states, identifiers, and source limitations. | `topic`, optional `filter` |
| `uslobbying_dataframe_query` | Materialize read-only SQL results and retrieve whole rows in count-bounded windows. | `canvas_id`, `sql` or `result_table`/`offset`, `row_limit`, optional `register_as` |
| `uslobbying_dataframe_describe` | Inspect staged tables, columns, acquisition coverage, and provenance before querying. | `canvas_id`, optional `table_name` |
| `uslobbying_dataframe_drop` | Remove a staged table before expiry when deletion is enabled. | `canvas_id`, `table_name` |

No resources or prompts of its own, and no app tools; the one listed resource is the published `us-lobbying-guide` skill, served by `createApp({ skills: 'skills' })` as `skill://us-lobbying-guide/SKILL.md`. Tool-only clients can complete every workflow. Upstream tools use `readOnlyHint: true`, `idempotentHint: true`, `openWorldHint: true`; reference and dataframe describe use `openWorldHint: false`. Dataframe query creates derived local state: use `readOnlyHint:false`, `destructiveHint:false`, `idempotentHint:false`, `openWorldHint:false`; repeated new SQL calls can create separate tables. Drop uses `readOnlyHint: false`, `destructiveHint: true`, `idempotentHint: true`, `openWorldHint: false` because it removes an existing table. Register drop through `disabledTool()` while `USLOBBYING_DATAFRAME_DROP_ENABLED` is false, retaining the manifest enable hint.

## Overview and requirements

Official US federal influence disclosures for journalists, ethics researchers, governance analysts, policy advocates, and compliance researchers. LDA covers registrations, quarterly activity (semiannual through 2007), covered-position disclosures, and semiannual contribution reports. FARA covers foreign-principal representation, individual short forms, and filing-document links. Neither source establishes wrongdoing, current employment, policy outcomes, or influence scores.

1. Find activity or registration filings and follow their official documents.
2. Resolve a client across retained firms without conflating similarly named entities.
3. Compare reported amounts by year and issue without counting amendments or income/expense overlap twice.
4. Trace a lobbyist's disclosed positions to the filing that actually contains them.
5. Inspect LD-203 contribution lists without confusing reports with individual donations.
6. Find FARA registrants by name or represented country, then inspect registration details.
7. Stage acquired analytical records and join/group them with SQL.

Support Bun and Node, STDIO and Streamable HTTP; `sessionMode: 'stateless'` is sufficient because continuations and canvases are server-side tokens rather than MCP session state. The public Streamable HTTP endpoint is https://us-lobbying.caseyjhand.com/mcp. Workers are outside this build: native DuckDB is unavailable there. Anonymous upstream access is the baseline; no key is needed. Keep current project version metadata unchanged during implementation.

LDA responses include access timestamps and the attribution: “Senate Office of Public Records cannot vouch for the data or analyses derived from these data after the data have been retrieved from LDA.gov.” Preserve source text and identify computed fields as derived; never use the Senate Seal. The [LDA API terms](https://lda.gov/api/tos/) permit end use but prohibit misrepresentation and throttle circumvention. FARA's [API](https://efile.fara.gov/ords/fara/f?p=API:ENDPOINTS) and [bulk repository](https://efile.fara.gov/ords/fara/f?p=107:21) explicitly support machine access and bulk download; no additional license or AI-specific permission was found there. This does not assert unrestricted rights in every attached PDF.

LDA page size is at most 25. Filings/contributions require a real filter to paginate beyond page one. Anonymous budget is 15/minute per originating IP; registered keys share 120/minute per user. Constants are exempt but may still share the conservative local pacer; the service caches each constants topic for 24 hours, shared by code validation and the reference tool, and never caches a failed fetch. FARA documents 5 requests per rolling 10 seconds shared across endpoints. Requests spaced 2.1 seconds apart still encountered 429s; runtime uses a conservative 4.1-second start gap and honors cooldown.

Runtime search uses the official daily XML ZIP alternatives because the CSV snapshots contain unescaped interior quotes and cannot be parsed completely without guessing field boundaries. `FARA_All_Registrants.xml.zip` is 313922 bytes, inflates to 2483177 bytes, and contains 7097 `REGISTRANTS/ROW` records. `FARA_All_ForeignPrincipals.xml.zip` is 971725 bytes, inflates to 9058184 bytes, and contains 17776 `FOREIGNPRINCIPALS/ROW` records. Both parse as well-formed XML after lossless Latin-1 decoding. Registrant XML fields include `Registration_Number`, `Registration_Date`, optional `Termination_Date`, `Name`, and sparse address/business fields. Principal XML uses `Foreign_principal`, `FP_registration_date`, optional `FP_termination_date`, `Country_location_represented`, `Registration_number`, `Registration_date`, and `Registrant_name`. Preserve missing elements, strings, whitespace, XML-decoded entities, and unknown fields; omitted termination elements identify active records in these snapshots. Of 17776 principal records, 16629 lacked ZIP and 15165 lacked city. Short-form search uses `FARA_All_ShortForms.xml.zip`, whose `SHORTFORM_REGISTRANTS/ROW` records carry `Short_form_first_name`, `Short_form_last_name`, `Short_form_date`, optional `Short_form_termination_date`, `Registration_number`, `Registration_date`, `Registrant_name`, and sparse address fields; omitted termination identifies an active short form. Registrant and principal snapshots suffice for their own searches: the short-form snapshot downloads only for a short-form search, and the document corpus is never downloaded.

FARA JSON field adapters are endpoint-specific, not a recursive case converter. Registrant list keys include `Registration_Number`, `Registration_Date`, `Name`, optional `Business_Name`, `Address_1`, `Address_2`, `City`, `State`, `Zip`. Principal detail uses `REG_NUMBER`, `REG_DATE`, `REGISTRANT_NAME`, `FP_NAME`, `FP_REG_DATE`, optional `TERMINATION_DATE`, `COUNTRY_NAME`, `ADDRESS_1`, `ADDRESS_2`, `CITY`, `STATE`, `ZIP`. Short forms use `REG_NUMBER`, `REG_DATE`, `REGISTRANT_NAME`, `SF_FIRST_NAME`, `SF_LAST_NAME`, `SHORTFORM_DATE`, optional `SF_TERM_DATE`, and uppercase address fields. RegDocs uses `REGISTRATION_NUMBER`, `DATE_STAMPED`, `REGISTRANT_NAME`, `DOCUMENT_TYPE`, `URL`, `SHORT_FORM_NAME`, `FOREIGN_PRINCIPAL_NAME`, `FOREIGN_PRINCIPAL_COUNTRY`. Require identifying fields, allow absent/null optional fields, preserve additional source keys. Validate complete raw JSON/XML trees with `JsonValueSchema` before endpoint schemas; unsupported own `__proto__` keys fail `source_schema_changed` rather than disappearing during object parsing. Reject an XML `__proto__` element before XML parsing for the same reason. Normalize only the verified envelope alternatives (row array, singleton object, empty rowset string); other shapes are schema failures.

## Shared input, output, and acquisition rules

All schemas use serializable Zod types and descriptions on every field; input roots and nested filter objects are strict. No arbitrary upstream parameter bag. Normalize blank optional strings to omitted, trim identifier whitespace, uppercase issue/filing codes, lowercase enumerated modes, and normalize canonical UUID casing. Numeric IDs are digit strings; accept losslessly validated safe upstream integers at the source edge and serialize as strings. Never round an unsafe upstream number. Names remain literal text; no fuzzy merging. Unknown issue/state/country/type values fail with a named reference-tool recovery.

Each data response includes `source` (`lda` or `fara`), `retrieved_at` ISO timestamp, `effective_filters`, `notices:string[]`, and `coverage`. LDA includes `attribution` verbatim above. Coverage is `{complete:boolean, pages_fetched:number, records_fetched:number, unique_records:number, upstream_count?:number, started_at:string, finished_at?:string, next_cursor?:string}`. `upstream_count` sums each partition's latest observed source-envelope count only when every partition count is known; duplicate source rows can contribute, so it differs from deduplicated `unique_records`. A completed sequence means links exhausted, not a transactionally frozen upstream snapshot. FARA adds `snapshot_retrieved_at`, `snapshot_source_urls`, and `snapshot_last_modified?` when the server actually supplied that header.

LDA list tools accept positive integer `page_size`, `max_pages` (default 1 for discovery, 5 for analytics, clamped to 5), and optional opaque `cursor`. `page_size` counts whole delivered records or rows, never upstream pages; every upstream LDA request asks for LDA's maximum page of 25. FARA returns one locally paged result window per call and has no `max_pages` input. Defaults and ceilings per unit:

| Tool and mode | Unit | Default | Ceiling |
|:--|:--|--:|--:|
| `uslobbying_search_filings`, `uslobbying_get_contributions` | filing, LD-203 report | 10 | 25 |
| `uslobbying_search_lobbyists` search, `uslobbying_get_client_profile` resolve | identity, candidate | 25 | 25 |
| `uslobbying_search_lobbyists` activity | evidence row | 25 | 1000 |
| `uslobbying_get_client_profile` profile, `uslobbying_get_issue_spending` | analytical row | 25 | 250 |
| `uslobbying_search_foreign_agents` | FARA record | 25 | 1000 |
| `uslobbying_list_reference` | entry | fixed 125-entry window, no count input | — |
| `uslobbying_dataframe_query` `row_limit` | SQL row | 25 | 100, then any lower provider ceiling |

Normalize delivery controls before scope comparison; `page_size` is scope identity, while `max_pages` and `cursor` are workload controls. Source response builders include `delivery_limits` with `{requested,effective}` pairs for this call's clamped controls; an empty map clears inherited disclosures and means no clamp. Over-cap values clamp and are logged and counted once on a first call; strict boolean `USLOBBYING_CLAMP_LIMITS=false` rejects them with `invalid_filter` naming the cap. Exact cursor replay retains its stored response and original disclosure. Nonpositive, fractional, nonnumeric and nonfinite controls fail. The page bound is a per-call workload limit with a continuation, never a corpus cap. Tool-call deadline is 45 seconds; individual network exchanges at most 20 seconds, retries included inside the remaining call deadline. If there is not enough time to start another page, return committed progress and a cursor; do not launch work after returning. A network failure fails the call, retaining the prior committed continuation so it can be retried.

Continuations live in tenant-scoped `ctx.state`, expire at a common absolute deadline 24 hours after acquisition starts, and bind the originating tool, normalized filters, scan kind, page/partition position, result chunk references, and acquisition start time. Echo `cursor_expires_at`; child chunks must not expire before their scan. Returned cursor tokens are random IDs, never arbitrary URLs. On continuation, unchanged filters may be omitted or repeated; changed filters reject. Query/mode fields on cursor-capable tools are optional in the advertised schema: requirements in the tool tables apply to the first call and are checked in the handler after cursor resolution. Resolve source `next` links only after verifying HTTPS, fixed host/path, allowed query keys, and page progression; rebuild the request from stored filters. Detect repeated pages/links and fail `pagination_invalid`, never mark complete. No endpoint URLs or credentials are caller supplied.

Use one mutable scan manifest with a monotonically increasing revision, a current random cursor, and the immediately preceding cursor's cached response and successor. Retrying the preceding cursor replays that response; advancing its successor replaces the replay slot. Older cursors fail `cursor_invalid` rather than restarting or advancing silently. Serialize operations for the same scan in a bounded process-local registry and release the lock on settle. Write new chunks before publishing the manifest through one `ctx.state.set`; deterministic chunk keys make retry after an interrupted chunk write safe. Acquisition failures must not publish a new revision. The framework does not promise a multi-key transaction or crash-atomic filesystem writes: an unreadable manifest/chunk invalidates the cursor with explicit restart recovery, never a partial success. A response lost after successful publication is recovered by the replay slot. This is a single-process service: shared storage does not make process-local locks or upstream budgets replica-safe. No per-revision checkpoint chain, per-row KV entries, or background continuation worker.

Keep acquired data in immutable independently stored chunks containing at most the current call's five source pages (125 rows at page size 25). Never rewrite a committed chunk while preparing another revision. Dedup-index shards use copy-on-write only for affected shards; the manifest selects the committed shard revision. Unpublished chunks/index revisions are ignored and may be safely overwritten on retry; reclaim replaced index shards after manifest publication. Do not use one key per UUID or a repeatedly rewritten full source array. Raw search cursors retain only undelivered rows, dedup state, and replay state; analytical scans retain all acquired rows until completion/expiry. Stream chunks for finalization instead of loading the full corpus and all three canvas tables into JS simultaneously. Source UUID deduplication is mandatory across pages and overlapping partitions. Upstream updates can still shift pages; disclose this live-API limitation rather than promising a historical snapshot.

The framework's default in-memory provider has a **10000-entry global ceiling**, not a configurable per-tenant unlimited store. One 96955-row year needs approximately 776 source chunks when every call commits five full pages (up to 3879 if calls commit only one), plus manifests/index shards; storing each response and historical checkpoint indefinitely would consume that budget unnecessarily. Bound retained in-memory acquisition data to 128 MiB process-wide, measured by serialized UTF-8 bytes including indexes/replay state, and refuse before advancing a checkpoint when capacity is unavailable. This is a resource refusal, never a successful truncated acquisition. Retain the in-memory default and warn that broad scans can exhaust it. An operator may explicitly select framework `STORAGE_PROVIDER_TYPE=filesystem` and a writable `STORAGE_FILESYSTEM_PATH` for larger durable scans; document the retained public records and expiry behavior rather than silently writing persistent copies. Filesystem storage removes the in-memory ceiling but still can fail on disk capacity. In either provider a missing chunk invalidates the cursor; never skip it or publish totals. Expiry or an in-memory restart requires a fresh scan; filesystem checkpoints survive restart until their absolute expiry. Capacity/disk failure preserves the last committed checkpoint where possible and returns `acquisition_storage_unavailable` with narrowed-scope/configuration recovery. A scan whose paced duration exceeds 24 hours requires separately requested year/client/registrant scopes; no claim of unlimited completion or automatic merging across independent scopes.

Delivery is count-based: every call returns exactly `min(page_size, remaining)` whole records or rows, and nothing measures bytes, because tool output size is the caller's `page_size` / `row_limit`, never a server-side budget that silently shrinks an explicit count. A page is short only at the end of the result or while acquisition is still collecting. Fetch source pages while fewer than `page_size` matches are pending, bounded by `max_pages` and the call deadline; retained windows read across the 125-row storage chunks and retain the undelivered tail. Analytical finalized lists/rows use the same windows with exact totals and a cursor even when acquisition is complete. Parent identity and nested list membership stay intact: an LD-203 report always arrives with its complete contribution list, and no size refusal exists.

`format()` carries every output value, null, nested field, notice, cursor, provenance field, and dataset pointer. Use a complete compact JSON text block for lossless structured data, choosing a fence longer than any run in source text; append official document URLs as Markdown links. This preserves CR/LF through JSON escapes and avoids lossy Markdown tables. Do not truncate specific-issues text, contribution lists, or FARA names. All upstream names, descriptions, covered positions, comments, and document titles are quoted record data, never instructions.

### Activity text selector

LDA activities carry long free-text descriptions and lobbyist lists that dominate filing size. `uslobbying_search_filings`, `uslobbying_search_lobbyists` activity mode, `uslobbying_get_client_profile` profile mode, and `uslobbying_get_issue_spending` accept optional unique `include` values `activity_descriptions` (`description`) and `activity_lobbyists` (`lobbyists`). A value left out strips that field from every lobbying activity in `filings`, `selected_filings`, `raw_filings`, `activities`, and `evidence[].activity`; nothing else is removed. Default is `[]`, or both values for `uslobbying_search_filings` with `filing_uuid`, which returns the complete record. Search-identity and resolve modes reject `include`. The selection is fixed for the scan: a continuation omits it or repeats it unchanged, `effective_filters.include` echoes it, and a notice names the fields left out. Analysis, totals, and canvas staging always use the complete records.

## Domain accounting

**Period selection.** For analytic ledgers, acquire all filing types for the selected year/client/registrant scope, not merely `Q1`–`Q4`. Exclude `RR`/`RA` from spending. Quarterly periods are `first_quarter` through `fourth_quarter`; semiannual periods are `mid_year` (`MM`, `MMY`, `MT`, `MTY`, `MA`, `MAY`, `M@`, `M@Y`) and `year_end` (`YY`, `YYY`, `YT`, `YTY`, `YA`, `YAY`, `Y@`, `Y@Y`). Group report/termination/amendment/no-activity variants of one period by `(registrant.id, client.id, filing_year, filing_period)`, deduplicate UUID, then choose greatest `dt_posted`. LD-2 reports were semiannual through 2007 and quarterly from 2008, so a registrant/client/year that filed both grains counts only its statutory grain and excludes the other as `off_cycle_period`; a year that filed one grain keeps it, so a 2008 relationship with only `MM` and `YY` reports still counts them. `non_quarterly` names only periods that are neither quarterly nor semiannual, and a filing type that does not match its period stays `unknown_variant`. Preserve `selected_filing_uuid`, all `superseded_filing_uuids`, and `selection_method:"latest_posted_within_relationship_period"`. This is a documented analytical rule, not an upstream-confirmed legal amendment chain. Equal latest timestamps with distinct UUIDs are `ambiguous` groups: retain candidates, exclude their amounts from sums, count and disclose them. Never use UUID lexical ordering to manufacture certainty. Unknown filing variants remain visible but excluded from aggregates pending explicit classification.

Apply issue/amount/text predicates **after** period selection for analytics: otherwise an amendment removing an issue can leave its superseded original counted. Search remains raw filing discovery and returns all matched versions, explicitly `amendment_policy:"all_versions"`. Empty-selection notices are evaluated per year: a year whose acquired filings select nothing gets a notice naming that year, even when another year in scope selects.

**Money.** Income and expenses are separate nullable decimal strings in USD. Parse decimal cents to `bigint` for exact addition, return decimal strings, and keep missing values missing. `0.00` is an explicit zero; null is unknown, not zero or a reportable threshold. Return known-value sums together with known/missing/ambiguous filing counts. Never derive a grand total by adding firm income to organization expenses: organization expenses can already include retained-firm payments ([official guidance, expense reporting](https://lobbyingdisclosure.house.gov/ldaguidance.pdf)). Do not infer a clean “in-house cost” by subtracting reported firm income. Expense-method codes A/B/C remain separate dimensions.

**Client identity.** LDA client records belong to registrant relationships; a client ID does not assert the complete corporate identity across retained firms. Select `candidates[].id`; preserve the registrant-assigned secondary `candidates[].client_id` without using it as the native filter ID. Name resolution returns all candidates with registrant, jurisdiction, effective date, and descriptions. A profile aggregates only caller-selected IDs and echoes them. Empty client/year partitions produce factual notices naming the ID and year, without inferring invalid identity from zero rows; acquired but excluded filings receive separate selection guidance. Empty-partition notices are retained as delivery rows after raw filings, rendered into `notices[]`, and counted in total delivery records while `row_set_totals` covers analytical sets only. Follow every bounded window. Do not merge parent/subsidiary, punctuation variants, or aliases automatically. The profile describes the selected records, never an unqualified “complete corporate footprint.” The `clients` breakdown has one row per client relationship record `id` (never the secondary `client_id`) with its registrant, selected filing UUIDs, and annual ledgers; each selected filing belongs to exactly one row, and `methodology.client_identity` is `relationship_records`.

**Issue amounts.** A filing has one income/expense amount and several activities. Count a filing once per requested issue, even if that issue appears in multiple activity rows. Preserve `issue_count` and `multi_issue_filing_count`; sums mean “reported amounts on filings mentioning this issue,” not issue-specific spending. Issue buckets overlap and cannot be summed into a national total. Activity child tables contain **no monetary amount**, preventing accidental multiplication when joined.

**LD-203.** `contribution_items` are report children, not the parent envelope's rows. Return full parent lists even if a contribution predicate selected the report, plus explicit `matched_item_indexes` computed locally using all item predicates on the same child. Local text predicates use case-insensitive literal substring matching; dates and type use exact normalized values. When child filters are present, omit candidate reports with no same-child match; with no child filters, every item index matches and no-contribution reports remain eligible. Deduplicate reports by UUID; preserve repeated identical child rows with `item_index` because the source provides no item ID. Retain amendments and their types in report search; do not offer cross-report donation totals that count original and amended lists together. PAC names identify disclosed PAC relationships, not proof that every item was paid by that PAC. Honorary/meeting/library/inaugural payments are distinct from FECA donations.

## Tools — detail

The common fields, coverage contract, and source models above apply to every subsection. Flat object inputs preserve fields in clients that flatten root unions. Mode-specific invalid combinations fail before any upstream request. Search no-hit notice is emitted only when the complete selected scope is exhausted; an empty intermediate page with `next_cursor` says the scan is incomplete.

### `uslobbying_list_reference`

| Parameter | Type | Mapping/behavior |
|:--|:--|:--|
| `topic` | `issue_codes\|filing_types\|government_entities\|contribution_types\|countries\|states\|identifiers\|methodology\|fara_rules` | Required on the first call; constants endpoints for the first six, authored source-specific explanations for the last three |
| `filter` | optional string | Case-insensitive literal token-AND match over the complete selected vocabulary, not an upstream search |
| `cursor` | optional opaque token | Continue the pinned filtered vocabulary; omit original topic/filter or repeat them unchanged |

Output: `topic`, `entries:[{value,name,source,description?}]`, `total_entries`, `matched_entries`, `retrieved_at`, `source_urls`, `notices`, and delivery fields `next_cursor`, `output_complete`, `truncated`, `offset`, `records_returned`, `cursor_expires_at`. Pin the complete filtered vocabulary once, then deliver a fixed window of up to 125 whole entries per call; the tool takes no count input. Cache constants for 24 hours in the LDA service, shared with filing-filter code validation; fetch complete arrays. `retrieved_at` is the shared constants fetch time (the older of the LDA and FARA retrievals for `countries`) and the call time for explanatory topics. `states` lists every LDA state entry. `identifiers` explains relationship IDs, UUIDs, FARA numbers, and continuation/canvas tokens; `methodology` carries amendment/amount/issue rules. Covered-position definitions are explanatory guidance, **not** a nonexistent constants endpoint. Countries combines LDA constants with FARA labels from the complete principal snapshot, marked by `source`; do not guess FARA ISO codes. Zero hits: “No reference entries matched; call uslobbying_list_reference with the same topic and omit filter.”

### `uslobbying_search_filings`

| Parameter | Type | Mapping/behavior |
|:--|:--|:--|
| `filing_year` | optional integer 1999–current UTC year | `filing_year`; require at least one substantive upstream filter |
| `client_id`, `registrant_id`, `lobbyist_id` | optional digit string | Same verified upstream names |
| `client_name`, `registrant_name` | optional string | Same names; upstream text matching, not entity resolution |
| `filing_uuid` | optional UUID | Native list filter; evidence and analytical selection UUIDs retrieve complete records, with `include` defaulting to both activity fields |

## DataCanvas contract

Completed analytical output uses flat typed fields: `annual_ledgers`, `selections`, `firms`, `clients`, `issue_codes`, `targeted_entities`, `selected_filings`, `activities`, and `raw_filings`. A shared cursor pages selected sets in that order; optional nonempty, unique `row_sets` selects inline delivery only. Omission delivers all sets, and `raw_filings` includes selected versions. Acquisition, analysis, SQL staging and `row_set_totals` remain complete. Normalized selections are cursor-bound; continuations may omit or repeat an equivalent selection, while changes fail `cursor_invalid`. Omitted sets remain available by restarting the same scope with another selection or through staged tables. `row_set_offsets` counts selected-set rows delivered before this window; unselected sets remain zero. Notices always follow domain rows regardless of selection, count in `total_records` and delivery counters, and are excluded from `row_set_totals`; offsets saturate at domain totals. A missing list in one window means no rows of that kind were delivered in that window, not an empty complete set.

Canvas is opt-in through framework `CANVAS_PROVIDER_TYPE=duckdb`; keep the default `none`. Install `@duckdb/node-api` as a production dependency for npm/Docker analytical capability. Wire the accessor in `setup(core)`. When canvas is enabled, a completed profile/issue scan stages all acquired and selected filings and selected activities; complete inline delivery remains available too. Use an explicit schema with no acquisition row cap. A supplied `canvas_id` means reuse that existing canvas, never silently mint a substitute if it expired. Final analytical responses include typed lists, `canvas_available`, and optional `dataset`; when canvas is disabled, return every final row through locally paged continuations and `canvas_available:false`, with no canvas token or claim that omitted rows are staged. These final-result cursors retain `status:complete` and complete acquisition coverage while advancing only the final row window; `coverage.next_cursor` still indicates remaining output. Explicit configuration errors and staging failures surface; never catch-log-return a successful incomplete table.

Dataset payload is `{canvas_id, tables:[{table_name,row_count,columns,grain,complete,created_at,expires_at}], describe_tool:"uslobbying_dataframe_describe", query_tool:"uslobbying_dataframe_query", guidance}`. Analytical delivery includes this schema on the first completed-acquisition window and its exact replay; later windows retain top-level `canvas_id`, `describe_tool`, `query_tool` and guidance without repeating table schemas. Guidance names actual table names and both tools. **Every response containing `canvas_id`, including dataframe tools and derived-table results, contains these pointers.** Register fresh names rather than replacing prior datasets. Provenance in tenant `ctx.state` is keyed by canvas and table; framework table metadata is authoritative for lifecycle/schema. No global shared tenant canvas hidden from the caller. A new caller without a token cannot enumerate existing canvases; possession of a token permits access to every table in that canvas. Under unauthenticated HTTP every caller shares tenant `default`, so tokens and query/filter history must not appear in logs or another caller's response. Canvas contains only the acquired public disclosures and their derived data, including source-published personal details; no credentials, private caller documents, or inferred private identities. Scope authenticated canvases through the framework tenant boundary.

Finalized analytical delivery traverses selected sets in the declared domain order, then notices, through the same source tool's cursor. Each response contains only the typed lists delivered in that window, exact `row_set_totals`, and `row_set_offsets` counting records already delivered; traverse the selected stream before clearing the final cursor. Top-level lists avoid redundant tagged wrappers and keep known schema paths within the formatter linter's depth. Default delivery retains complete acquired versions rather than requiring a fresh search against changed upstream data. Every summary is windowed by the same `page_size` count. With canvas, register every raw/selected/activity row before advertising the dataset. Partial tables never appear as complete; a staging timeout/failure retains acquisition state for retry and directs persistent failure to a narrower source scope. Selection consumes replayable chunks incrementally, retaining latest candidates and UUID decisions; raw table staging and final-record materialization replay those chunks without buffering another corpus. Canvas registration is one awaited operation per table; no detached ingestion or partial table append protocol.

| Table grain | Required columns and rules |
|:--|:--|
| One raw filing | UUID, registrant/client IDs, type/year/period/posting time, `income_usd VARCHAR`, `expenses_usd VARCHAR`, method, JSON disclosure fields, `selection_status`, and `selected_filing_uuid` linking superseded versions to the winner when unambiguous. Unknown fields remain in `source_fields`; the table always holds complete records, while inline rows follow `include`. Null stays null. |
| One selected relationship-period filing | Same money columns, selected UUID, `issue_count`, `ambiguous` flag; only unambiguous selected filings enter sums. |
| One filing/activity | UUID, zero-based activity index, issue code, description, JSON lobbyists/government entities. **No money column.** |

Related tables share the filing UUID. Source record and child JSON preserve nested/sparse fields. Explicit `ColumnSchema` types are supplied even when leading values are null or zero. The framework's column type union has no DECIMAL: keep monetary columns `VARCHAR`, and use `CAST(income_usd AS DECIMAL(38,2))` in SQL for exact sums. Never infer `BIGINT`/`DOUBLE` money columns from a preview. Synthetic example: `SELECT filing_year, SUM(CAST(income_usd AS DECIMAL(38,2))) FROM df_SYNTHETIC_SELECTED WHERE selection_status = 'selected' GROUP BY filing_year`; actual table names come from the dataset payload.

### Dataframe tools

| Tool | Inputs | Output |
|:--|:--|:--|
| `uslobbying_dataframe_describe` | Required `CanvasIdSchema`; optional existing `table_name` | Canvas pointers, `tables` containing exact row count, column name/type/nullability, grain, source tool, effective filters, acquisition coverage/timestamps, lifecycle timestamps. Empty canvas returns empty array; unknown named table throws `missing_table`. |
| `uslobbying_dataframe_query` | Required canvas ID; either nonblank `sql` plus optional fresh `register_as`, or `result_table` plus `offset` (nonnegative integer, default 0); positive integer `row_limit` default 25, clamped to 100 then a lower provider ceiling | Canvas pointers and dataset, `result_table`, `columns`, JSON-safe `rows`, exact `row_count`, `rows_returned`, `offset`, optional `next_offset`, `output_complete`, `row_order:"sql_result"`, `delivery_limits` (requested/effective pairs, empty when nothing was clamped), and `effective_row_limit` when a ceiling lowered the request. |
| `uslobbying_dataframe_drop` | Required canvas ID and table name | Canvas pointers, requested table name, `dropped:boolean`; absent table is false. Unknown canvas uses the drop-specific recovery below. |

Query delegates the single-statement SELECT/CTE gate and file/network/extension denial to DataCanvas. Preserve its `invalid_sql`, `missing_table`, `sql_execution_error`, `non_select_statement`, `multi_statement`, `denied_function`, `sql_read_only`, `plan_operator_not_allowed`, `sql_parse_error`, and `register_as_clash` distinctions; do not rebuild SQL parsing with regexes. Materialize each new SQL result through `query({registerAs, preview:0})`, using the caller's fresh name or a generated fresh name, so even the first response has an exact count and a stable remaining-data handle. Delivery windows read the materialized table back unchanged: `SELECT * FROM <quoted-result-table> LIMIT <validated-window> OFFSET <validated-offset>`, because a caller's ranked query is only useful if its first window is the top of the ranking. DuckDB's default `preserve_insertion_order` keeps a top-level `ORDER BY` through materialization; an `ORDER BY` only inside a CTE or subquery does not guarantee it, and a query without one keeps the order DuckDB produced, fixed once materialized. Report this as `row_order:"sql_result"` and state it in the tool description, the dataset guidance, and both `offset` descriptions. Advancing by delivered rows preserves duplicate multiplicity. Retrieval accepts only a known materialized result table belonging to this canvas; changing SQL requires a fresh materialization. No OFFSET continuation over a re-executed, unordered original query, and no separate query-cursor store.

Each call returns exactly `min(row_limit, remaining)` whole rows, where `row_limit` is at most `min(100, framework canvas row limit)`, because the caller's `row_limit` is the only bound on result size; nothing measures bytes. Advance `next_offset` by the number delivered. When a ceiling lowers the request, include `effective_row_limit` and `delivery_limits.row_limit:{requested,effective}`. The full materialization remains reachable via the returned `result_table`/`next_offset` in this same tool; `output_complete` concerns delivery, not table completeness. An `offset` equal to the table's `row_count` returns zero rows and a larger one fails `invalid_filter`. Do not silently trim strings or drop columns. BIGINT/DECIMAL values follow the provider's lossless JSON serialization. Expired/dropped materializations fail `missing_table`; restart the original SQL only by an explicit new call.

MCPB cleaning deliberately strips platform DuckDB natives. `manifest.json` therefore fixes `CANVAS_PROVIDER_TYPE=none`; bundle installs expose inline data and actionable `canvas_unavailable` from dataframe tools. Do not offer a bundle setting that promises working DuckDB. npm/Docker users can enable canvas; an explicitly enabled but missing/broken native fails honestly. No runtime native download or automatic filesystem installation.

## Services, config, and resilience

| Module | Responsibility |
|:--|:--|
| `src/services/lda/lda-service.ts` | Fixed-host requests, strict filter allowlists per noun, wire schemas, constants, page/detail methods; one source pacer |
| `src/services/fara/fara-service.ts` | Fixed-host Latin-1 JSON requests, source-envelope normalization, selected daily XML ZIP snapshots, local filtering; one shared pacer for API/bulk |
| `src/services/acquisition/acquisition-service.ts` | Tenant continuations/checkpoint chunks, page/partition traversal, UUID dedup, deadline/progress, replay behavior |
| `src/services/lobbying/analysis.ts` | Pure latest-period selection, client-scope joins, exact money ledgers, issue membership and uncertainty accounting |
| `src/services/canvas/canvas-service.ts` | Accessor, explicit table schemas, complete staging, provenance and consumer-facing recovery routing |
| `src/config/server-config.ts` | Lazy validated optional LDA token, drop flag, and clamp flag |

One initialized LDA pacer process-wide: `{requests:15,perMs:60000}`, `minStartGapMs:4100`, `maxConcurrent:1`; with an optional configured key use 120/minute and 510 ms gap. One FARA pacer process-wide: `{requests:5,perMs:10000}`, 4100 ms gap, concurrency 1. Both bound queue depth (32 waiters) and queue wait by the call's remaining deadline. Cross-tool calls and retries share their source pacer; tenants do not get independent upstream budgets. Separate processes sharing an originating IP remain a deployment constraint. No per-session pacer, detached refresh timer, or request-start race.

Use framework `createPacer` inside `withRetry`, wrapping fetch **and body read**; at most one retry per page within the tool's 45-second deadline. Retry transient network/408/429/500/502/503/504 only, never schema errors or other 4xx. Honor capped Retry-After and pacer cooldown (FARA base 10 seconds/max 30 seconds). Cancellation reaches queue, exchange, parser iteration, and canvas registration; do not swallow caller abort. HTML received for a successful JSON request is an upstream availability failure; valid but incompatible JSON is schema change. FARA non-JSON 429 is classified by status before parsing. No speculative retry of arbitrary thrown errors.

FARA snapshot cache is process-wide, shared public data, single-flight per dataset, TTL 24 hours, at most the three search datasets (registrants, foreign principals, short forms); no unbounded query-key cache. First request downloads only required snapshots; principal and short-form searches join the registrant snapshot for `registrant_status` and the listing URL. Pin each search's matched rows and snapshot provenance into its continuation chunks, so cache refresh between calls cannot skip, duplicate, or change that search's results. Refresh is awaited in-request, never detached. Extract ZIP members in memory without writing member paths to disk. Decode declared ISO-8859-1 bytes losslessly before parsing using Node `Buffer.toString('latin1')` (also supported by Bun); Web `TextDecoder('iso-8859-1')` aliases Windows-1252 and does not preserve the ISO C1 byte range. Validate complete XML with a real XML parser, disable numeric coercion and whitespace trimming, decode built-in entity references, and reject DTD/entity declarations. The framework XML convenience wrapper does not expose the required lossless options, so use its vetted `fast-xml-parser` peer directly. Validate root/row shapes and records; do not accept an HTML error ZIP or infer zero rows from parsing failure. Keep source spellings and raw dates alongside normalized calendar dates. ## Verification strategy

Inject the network boundary (`fetch`-compatible transport) into source services and keep source parsers and accounting pure. Use synthetic fixtures with real field names, never copied personal records. Fake timers drive process-wide pacing, retries, deadlines, cache TTL, and continuation expiration; no sleeps or wall-clock assertions. Use `createMockContext()` for definitions and exercise the framework invocation boundary for argument and output parsing.

Required cases: LDA 25-row pages and different next pages; ignored upstream parameter prevented by allowlist; zero/malformed/404; duplicate UUIDs across pages; item-filter duplicate parent reports; unknown/sparse nested fields; null versus zero amounts; original/amended/no-activity/termination selection; issue removed by later amendment; duplicate same-issue activities; equal-time ambiguity; cross-firm client IDs never auto-merged; expense/income never added; exact large/fractional decimal arithmetic; contribution no-items/PAC/null and mixed matching/nonmatching children; FARA missing address fields and numeric/string IDs/ZIP; singleton/array/ROWSET-empty; ISO-8859-1 accents/C1 bytes, XML entities, literal quotes, multiline XML values and postal leading zeroes; DTD rejection and malformed XML never partial success; separate principal/registrant status; live plain-text 429 and HTML errors; snapshot failure never empty success.

Continuation tests prove every synthetic source row is eventually reachable, no page or undelivered tail is skipped on a deadline, immediate replay does not duplicate progress, older cursors reject, interrupted writes preserve the prior manifest, malformed/off-origin next links fail, changed filters fail, and incomplete scans never expose final totals. Include default-provider entry/byte exhaustion, lost chunks, absolute expiry during a long scan, filesystem restart recovery, and FARA cache refresh during pagination. Concurrency tests call different tools simultaneously and prove a single source budget, including retries. Cancellation leaves no detached work or partial advertised table. Delivery tests assert the exact count at each default and ceiling, the clamp and its `delivery_limits` disclosure, and `invalid_filter` with `USLOBBYING_CLAMP_LIMITS=false`, with filings of several hundred kilobytes delivered whole. Canvas tests inspect explicit schema with null-leading money, complete staged rows versus preview, pointers on **every** canvas-token branch, exact materialized count, multi-window `ORDER BY ... DESC` and tie-heavy queries on a real DuckDB canvas returning the query's order without duplicates or gaps, rows paged exactly once for queries without `ORDER BY`, the zero-row window at `offset == row_count`, expired token/table recovery, DROP/ATTACH/COPY/external read denial, drop enabled/disabled registration, and MCPB no-native delivery of every acquired raw/selected/activity row.

For every tool, inspect both structuredContent-only and content[]-only results, including errors, empty rows, long multiline descriptions, source links, nested lists, cursors, notices, and dataset metadata. Round-trip the JSON text block and compare every field to structured output; separately verify document links. For large source parents, assert that whole records reach both surfaces unchanged, including unknown keys, large child arrays, and multibyte strings, without a duplicated source_record copy, and that `include` removes only the activity fields it leaves out.

Run `bun run devcheck` raw, `bun run test`, and `bun run rebuild`; independent verification owns authored tests. A later paced live field pass covers each registered tool, continuation completion on a narrow scope, sparse/empty cases, one exact accounting example, enabled canvas SQL and disabled drop, and both response surfaces. No deliberate quota exhaustion and no production listener or deployment is needed for this design.

## Known limits and decisions

The broad issue workflow is intentionally expensive because the official LDA API has no verified issue-code filter and limits pages to 25. Resumable acquisition makes this honest; partial sums would make it misleading. Large live scans are not immutable snapshots and may expire before completion. Explicit selected client IDs preserve the footprint workflow without pretending the source offers a corporate identity graph. Latest-posted selection is reproducible but not proof of a legal amendment lineage. Reported amounts are rounded estimates with gaps; issue associations and contribution categories do not establish policy influence. FARA bulk search is daily rather than live, and no registration number is a general cross-source identity. These limitations are returned with results, not hidden in README prose alone.
